# Feature: Postgres-backed WifiOrderStore (gap C for WiFi orders)

## Objective
A Drizzle/Postgres implementation of the WiFi order store, shared by `bff-api` and `bff-worker` through the same `DATABASE_URL`, so a paid order written by the API is visible to the worker jobs (activation, SIR, e-receipt) and `wifi.checkout` can be enabled in production without tripping the fail-fast guard.

## Why
Code review of PR #19 (confirmed): API and worker each default to a private in-memory order store, so the worker never sees API orders. A production guard now fails loudly when `wifi.checkout` is on without a shared store; this feature removes the root cause for WiFi orders only.

## Scope
- In: `WifiOrderStore` Postgres adapter + migration + wiring in `main-api.ts` / `main-worker.ts`; atomic compare-and-swap `transition` (also closes the review finding that SIR/receipt writes can undo a refund transition); tests against a real Postgres.
- Out: Postgres adapters for other stores (push, pulse, analytics, access-link, ...), the remaining medium/low review findings, any change to flag defaults.

## Constraints
Strict TDD (bff: `pnpm --filter bff exec vitest run --no-file-parallelism`); follow the existing Drizzle/migration conventions (task 3.3 tables); no TLS weakening, no sudo, agent must not push or touch PRs. ## Progress / evidence
### T1 findings (conventions + contract), route: delegated direct (one writer)
- Drizzle conventions (task 3.3): schema in `services/bff/src/infra/db/schema.ts` (pgTable, uuid pk `defaultRandom()`, `timestamp(..., {withTimezone:true}).notNull().defaultNow()`, `pgEnum` for closed sets, snake_case columns); migrations generated by `pnpm --filter bff db:generate` (drizzle-kit, `drizzle.config.ts`, out `src/infra/db/migrations`, journal in `meta/`); schema/migration tests are static (`schema.test.ts` via getTableColumns, `migrations.test.ts` reads the SQL).
- NOT present today: any Drizzle db client factory, any Postgres-backed store, any migration runner (compose/Dockerfile/infra apply none), any real-Postgres test, any Testcontainers. Only pg-boss uses `pg` (`infra/queue/pg-boss-queue-client.ts`, creates its own `pgboss` schema). So this feature adds the first client factory, the first store and the first migration step; everything else follows the existing conventions.
- `WifiOrderStore` (`modules/wifi-checkout/ports.ts`): `findByIdempotencyKey`, `findById`, `create` (idempotent per key, status CREATED), `transition(id, toStatus, patch)` (unknown id throws `WifiOrderNotFoundError`; merge-patch of 10 fields; toStatus MAY equal current; appends one `wifi_order_event`), `listEventsForOrder` (transition order), `listByStatus`. Records carry ISO-string timestamps.
- Gap found: the in-memory `transition` does NOT enforce an expected status (callers pass `order.status` read earlier and overwrite blindly), which is the review finding (SIR/receipt writes can undo REFUND_PENDING/REFUNDED). Callers: create-wifi-order (CREATED->PAYMENT_PENDING), handle-payment-webhook, activate-wifi-order (PAID->ENTITLEMENT_ACTIVE), wifi-order-jobs (3 same-status patch writes).
- Decision: `transition(id, expectedStatus, toStatus, patch)` becomes a compare-and-swap returning `WifiOrderRecord | null` (null = status was not `expectedStatus`, nothing written, no event); unknown id still throws `WifiOrderNotFoundError`. Both stores implement it; callers treat null as a graceful no-op (re-read and return the current order), never throw.
- Test infra decision: DB-backed tests read `TEST_DATABASE_URL`; skipped with an explicit console warning when unset (never silently pass). Local: compose postgres on localhost:5432, database `travel_hub_test`.
- Production guard in composition-root (buildApp/startWorker throw when wifi.checkout on + production-like + no orderStore) is kept.
